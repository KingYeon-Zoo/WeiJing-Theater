# 分镜拆解 (Storyboard Breaker)

本技能供 `storyboard_breaker` Agent 使用。剧本是文科生的艺术，分镜则是理科生的图纸。
在微境的管线中，所有的镜头最后都将进入语音、影像、剪辑模块。如果你拆的镜头含糊不清、甚至绑定了不存在的人和地名，整个工业链将会崩溃。

## 拆解策略

### 1. 从阅读开始
无论何时，开始前必须调用 `read_storyboard_context`。这会给你最宝贵的资源：当前剧本内容，以及经过验证的合法角色名单和合法场景名单。
如果你自己凭空发明了名单之外的角色 ID（如“路人甲的ID 999”）或地点，系统将报错。

### 2. 时空解构与单一性
- **一个镜头承担一个核心画面动作**：如果一个镜头中，主角既要走过一条街，又要坐下来吃饭还要聊天聊十分钟，这在视觉呈现中是做不到的。必须拆成多个。
- **推荐的时长 (duration)**：系统推荐单个微镜头长度为 10 到 15 秒为主。根据实际情况加减，但总体不能出现一分钟的长镜头。如果有极高信息量的拉扯对白，可以多镜头组合。

### 3. 数据层面的专业主义
使用 `save_storyboards` 时，你需要尽可能充实字段：
- `title`：作为书签使用的3-8字标题，能够让人通过标题就回忆起画面。
- `shot_type` / `angle` / `movement` 决定了机位的绝对态度。请专业判断（全景 / 特写 / 仰拍 等）。
- `image_prompt`: 当系统需要直接生图时使用的画面引导词。
- `bgm_prompt` / `sound_effect`: 必须提供恰当的环境声频与配乐氛围提示。
- `action` vs `dialogue`: 如果某个镜头角色沉默不语，完全可以空置 dialogue，但你的 `action` 和 `description` 必须足以撑起这十几秒的时长。

### 明确底线
你必须优先复用 `read_storyboard_context` 所返回合法的 `scene_id` 与合法的 `character_ids`。如确实有无人的空镜（例如窗台滑过一滴雨），角色可空或者放空数组，但地点绝不可凭空捏造与环境脱节的设定。
